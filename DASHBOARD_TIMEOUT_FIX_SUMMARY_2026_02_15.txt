THE PROBLEM
================================================================================

Issue: /dashboard route throws "Maximum execution time of 30 seconds exceeded"

Symptoms:
  • Dashboard page hangs/timeouts after 30 seconds
  • Backup management pages also affected
  • Timeout occurs on every request (not cached)
  • Error logs show: Filesystem.php:493

Timeline:
  • First reported: 2026-02-15 02:52:06
  • Repeated: 2026-02-15 03:53:02
  • Triggered by: Recent registration page changes (import modal, layout updates)

User Impact: Users cannot access dashboard, system appears frozen

================================================================================
ROOT CAUSE ANALYSIS
================================================================================

Location: resources/views/filament/admin/pages/manage-backups.blade.php:52-70

Problematic Code:
  @php
      foreach (glob(storage_path('backups/sqlite/*.enc')) as $file) {
          $totalSize += filesize($file);
      }
  @endphp

Why It's Slow:
  1. glob() recursively scans backup directory
  2. filesize() makes system calls for each file
  3. No caching - recalculates on EVERY request
  4. With 1000+ backups = 10-30 second operation
  5. Executes even if user never visits backup page

Why Recent Changes Triggered It:
  • Registration page updates caused view recompilation
  • Blade cache invalidation
  • Exposed this hidden bottleneck in filament views

Why Not Caught Earlier:
  • Code was already slow, but not triggered frequently
  • Most users don't visit backup management page
  • New import features + modal = more active views

================================================================================
THE SOLUTION
================================================================================

Approach: Professional caching with error handling

Core Changes:

1. NEW SERVICE: app/Services/BackupStatisticsService.php
   Purpose: Cache backup statistics instead of scanning on every request
   
   Features:
   • Caches results for 1 hour (configurable)
   • Scans only first 1000 files (safety limit)
   • Proper error handling & logging
   • Format utilities (bytes → human-readable)
   
   Methods:
   - getTotalBackupSize() - Returns cached size or calculates
   - calculateBackupSize() - Scans directory safely
   - clearCache() - Called after backup operations
   - formatBytes() - Converts to "2.45 GB" format

2. UPDATED VIEW: resources/views/filament/admin/pages/manage-backups.blade.php
   Changed from: Direct glob() call
   Changed to: Service call via BackupStatisticsService
   
   Result: ~20 lines of slow code → 3 lines of fast code

3. UPDATED CONTROLLER: app/Http/Controllers/BackupManagementController.php
   Changes: Clear cache when backups created/deleted
   
   Methods Updated:
   - create() - Clears cache after creating backup
   - delete() - Clears cache after deleting backup
   
   Benefit: Ensures next page load shows accurate data
