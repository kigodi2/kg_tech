ARCHITECTURAL STRUCTURE PROPOSED
================================================================================

LIFECYCLE PHASES (7):
  1. ENTRY          - Teacher uploads marks via CSV/ZIP
  2. VALIDATION     - System validates data (automated)
  3. MODERATION     - HOD/Supervisor reviews & approves (human gate)
  4. PROCESSING     - Grades calculated (automated)
  5. REPORTING      - Reports generated (automated)
  6. SUBMISSION     - Formally locked for exam authority
  7. AUDIT TRAIL    - Complete operation history visible

SIDEBAR MENU GROUPS (6):
  📊 ENTRY & VALIDATION      - Upload, templates, error batches
  🔍 MODERATION & REVIEW     - Review dashboard, approve/reject
  🔒 SUBMISSION & LOCKING    - Lock status, submit, unlock
  📑 REPORTS & EXPORTS       - Scoresheets, CSV exports, analytics
  🕐 MONITORING & AUDIT      - Lifecycle dashboard, audit trail
  ⚙️  ADMINISTRATION          - Configuration, access control

STATE MACHINE (11 States):
  draft → validating → validated → awaiting_moderation → approved → submitted
                      ↓              ↓                      ↓
          validation_failed      rejected ← (fixes) ← draft
                                   ↓
  processing → processed → archived

CONTROLLERS (8):
  MarkEntryUploadController              (Entry phase)
  MarkValidationController               (Validation phase)
  MarkEntryModerationController          (Moderation phase)
  MarkEntrySubmissionController          (Submission phase)
  MarkEntryReportController              (Reporting phase)
  MarkEntryMonitoringController          (Audit phase)
  MarkEntryAdminController               (Configuration)
  MarkEntryApiController                 (Shared filtering)

SERVICES (Organized by phase):
  LifecycleStateService                  (State machine)
  MarkModerationService                  (Moderation workflow)
  MarkValidationService                  (Validation rules)
  AuditTrailService                      (Change logging)
  MarkLockingService                     (Lock/unlock)
  ... (and others)

DATABASE CHANGES:
  NEW TABLES (4):
    - mark_entry_lifecycle_states        (State transitions)
    - mark_moderation_reviews            (Moderation records)
    - mark_entry_changes                 (Change tracking)
    - mark_batch_approvals               (Approval signatures)
  
  ENHANCED TABLES (2):
    - mark_import_batches                (Add state machine columns)
    - raw_marks                          (Add audit columns)
