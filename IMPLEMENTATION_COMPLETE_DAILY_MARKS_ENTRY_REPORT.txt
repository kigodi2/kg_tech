DATA FLOW & ARCHITECTURE
═════════════════════════════════════════════════════════════════════════════

USER INTERFACE (Frontend):
  1. User navigates to: Evaluations > ENTRY REPORT > REGIONAL LEVEL > SUBJECTS
  2. Page loads with sidebar menu and content area
  3. User sets filters: Year, Region, Subject, Date
  4. Alpine.js initializes data component
  5. Dropdowns populate from API calls

DATA RETRIEVAL:
  1. User changes any filter
  2. JavaScript triggers API call
  3. Request sent to: GET /api/daily-marks-entry-report?params
  4. Controller receives request

BACKEND PROCESSING:
  1. DailyMarksEntryReportController.getReport() receives request
  2. Builds query with SubjectMarks relationships
  3. Applies filters: exam_year, region, subject, entry_date
  4. Executes database query with eager loading
  5. Processes results in generateReport()
  6. Groups by subject, calculates daily breakdown
  7. Calculates percentages and expected scripts
  8. Generates remarks based on completion %
  9. Returns JSON array

RESPONSE:
  1. JSON returned to frontend
  2. Alpine.js receives data
  3. Updates reportData array
  4. Blade template x-for loops render rows
  5. Table displays with data binding

USER ACTIONS:
  1. Click Export CSV → JavaScript triggers CSV generation
  2. CSV downloads via blob URL
  3. OR: Click Print → Opens print preview window
  4. Print preview shows formatted table
  5. User can print from preview

DATABASE:
  Tables used:
  - subject_marks (main data)
  - subjects (lookup)
  - candidates (user context)
  - schools (region lookup)
  - regions (grouping)
