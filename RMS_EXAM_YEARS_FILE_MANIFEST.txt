================================================================================
COMMON ISSUES & SOLUTIONS
================================================================================

Duplicate column error
  → Column already exists
  → DROP COLUMN and retry

Foreign key constraint fails
  → exam_year_id references non-existent year
  → Run validation queries
  → Check for orphaned values

"Only one active year" error
  → Multiple years marked active
  → Use stored procedure to switch

Migration hangs
  → Long-running UPDATE on large table
  → Monitor: SELECT COUNT(*) FROM candidates WHERE exam_year_id=0;

Cannot write to locked year
  → This is EXPECTED behavior
  → Only published years are locked

================================================================================
VERIFICATION QUERIES (RUN AFTER MIGRATION)
================================================================================

Check no NULLs:
  SELECT * FROM candidates WHERE exam_year_id IS NULL;
  -- Expected: 0 rows

Check referential integrity:
  SELECT * FROM candidates c
  LEFT JOIN exam_years y ON c.exam_year_id = y.id
  WHERE c.exam_year_id > 0 AND y.id IS NULL;
  -- Expected: 0 rows

Check lock enforcement:
  INSERT INTO marks (..., exam_year_id=1) VALUES (...);
  -- If year 1 locked: ERROR 1644

Check year counts:
  SELECT id, year_label, is_active, is_locked FROM exam_years;

Check data distribution:
  SELECT exam_year_id, COUNT(*) FROM candidates GROUP BY exam_year_id;
