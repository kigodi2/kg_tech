================================================================================
QUICK START: PRIVATE CANDIDATE SUBJECT ALLOCATION
================================================================================

WHAT IS IT?
  Import PRIVATE candidates with a 'subjects' column → automatic allocations

HOW TO USE:
  1. Prepare CSV with subjects column (pipe-delimited codes)
  2. Upload via Candidates Import
  3. Allocations automatically created → Allocated Subjects column populates

================================================================================
CSV FORMAT (MINIMAL EXAMPLE)
================================================================================

SCHOOL CANDIDATE (existing, no changes):
  candidate_id,full_name,gender,school_code,exam_type,exam_year
  S0001-0001,John School,M,SCH001,ACSEE,2026

PRIVATE CANDIDATE (new subjects column):
  candidate_id,full_name,gender,school_code,candidate_type,subjects,exam_type,exam_year
  P0001-0001,John Private,M,SCH001,PRIVATE,111|102|103|121,ACSEE,2026

FULL EXAMPLE:
  candidate_id,full_name,gender,school_code,candidate_type,subjects,exam_type,exam_year
  P0001-0001,John Private,M,SCH001,PRIVATE,111|102|103|121,ACSEE,2026
  P0002-0001,Jane Private,F,SCH001,PRIVATE,111|104|121|122,ACSEE,2026
  P0003-0001,Bob Private,M,SCH001,PRIVATE,111|103|121|122,ACSEE,2026

SUBJECT CODE MEANINGS:
  111 = General Studies (MANDATORY)
  102 = Math
  103 = Physics  
  104 = Chemistry
  121 = English
  122 = Swahili
  
  (Check admin > Subjects for complete list)

================================================================================
VALIDATION RULES
================================================================================

MUST HAVE: General Studies (111)
  ✓ Valid: 111|102|103|121
  ✗ Invalid: 102|103|121 (missing 111)

MUST HAVE: ≥ 3 Principal Subjects (plus GS)
  ✓ Valid: 111|102|103|121 (1 GS + 3 principals)
  ✓ Valid: 111|102|103|121|122 (1 GS + 4 principals)
  ✗ Invalid: 111|102|103 (1 GS + 2 principals)

================================================================================
WHAT GETS ALLOCATED
================================================================================

For CSV row:
  P0001-0001,John Private,M,SCH001,PRIVATE,111|102|103|121

System creates 4 allocations in candidate_subject_selections table:
  1. candidate_id=P0001, subject=111 (General Studies), is_principal=false
  2. candidate_id=P0001, subject=102 (Math), is_principal=true
  3. candidate_id=P0001, subject=103 (Physics), is_principal=true
  4. candidate_id=P0001, subject=121 (English), is_principal=true

On /exam-types/acsee: Shows "102, 103, 111, 121" in Allocated Subjects column

================================================================================
WHAT'S SAFE (NOT DELETED)
================================================================================

These are PROTECTED and never deleted:
  ✓ Marks (in subject_marks table)
  ✓ Exam registrations (in candidate_exam_registrations)
  ✓ Results (in result tables)
  ✓ Candidate records (in candidates table)

Only this is MODIFIED:
  ⚠ Allocations (candidate_subject_selections) for that candidate+exam year

================================================================================
ERROR MESSAGES & FIXES
================================================================================

ERROR: "General Studies is mandatory"
  FIX: Add "111" to subjects: "111|102|103|121"

ERROR: "Minimum 3 principal subjects required"
  FIX: Add more subjects. Need GS + 3 others minimum.
       Example: "111|102|103|121" (4 total = 1 GS + 3 principal)

ERROR: "Subject not found"
  FIX: Check admin > Subjects page for correct codes

ERROR: "No valid subjects found"
  FIX: Verify subject codes/IDs match database

================================================================================
TIPS
================================================================================

TIP 1: SCHOOL vs PRIVATE
  - SCHOOL candidates: Use 'combination' column (e.g., "PCM")
  - PRIVATE candidates: Use 'subjects' column (e.g., "111|102|103|121")
  - Both can be in same CSV

TIP 2: IMPORTING SAME FILE TWICE
  - SKIP mode (default): 2nd import does nothing (candidate already exists)
  - REPLACE mode: 2nd import updates candidate name and reallocates subjects
  - Either way: No duplicate allocations (safe)

TIP 3: SUBJECT CODES vs IDS
  - Codes: "111|102|103|121" (preferred, human-readable)
  - IDs: "1|2|3|4" (also works if you know IDs)
  - Both supported in same column

TIP 4: COPY PASTE
  Easiest: Copy subject codes from email/documentation and paste into CSV
  
  Example from system:
    111 = General Studies
    102 = Math
    103 = Physics
    121 = English
  
  Paste into CSV:
    subjects: 111|102|103|121

TIP 5: VERIFY ALLOCATIONS
  After import, check:
    1. Go to EXAM TYPE → ACSEE
    2. Click Candidates tab
    3. Look for PRIVATE candidates
    4. "Allocated Subjects" column should show codes

================================================================================
TROUBLESHOOTING
================================================================================

Q: Allocations not showing on /exam-types/acsee?
A: Refresh browser (F5). Data is in DB, may be cached.

Q: Import succeeded but allocations_created_count=0?
A: Check if subjects column has valid codes. Errors logged in allocation_errors.

Q: Want to change allocations after import?
A: Re-import same CSV in REPLACE mode with different subjects.

Q: Marks disappeared?
A: They didn't. Marks are in different table. Check Marks page.

Q: How to undo an import?
A: Delete candidates (and marks if needed) from admin panel.
   Run import again or use REPLACE mode with correct data.
