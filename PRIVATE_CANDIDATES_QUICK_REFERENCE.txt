================================================================================

WHAT CHANGED?
- General Studies (111) is now OPTIONAL for PRIVATE candidates
- Minimum requirement: 1 subject (any subject)
- Subject codes work (111, 121, 131, etc.)
- Subject IDs also work (numeric IDs)

CSV FORMAT
----------
candidate_id,full_name,gender,candidate_type,school_code,exam_type,exam_year,subjects
P0652-5001,JOHN DOE,M,PRIVATE,P0652,ACSEE,2026,111|121|131|141
P0652-5002,JANE SMITH,F,PRIVATE,P0652,ACSEE,2026,122|132

KEY RULES
---------
✓ PRIVATE candidates MUST have a "subjects" column
✓ Subjects are pipe-delimited (e.g., 111|121|131)
✓ General Studies (111) is OPTIONAL
✓ Minimum: 1 subject
✓ Maximum: unlimited subjects
✓ Subject codes must exist in the database

VALID EXAMPLES
---------------
✅ 111|121|131|141      (With GS + 3 principals)
✅ 122|132|142          (No GS, 3 subjects)
✅ 121                  (Single subject)
✅ 111|121|131|141|151  (5 subjects)

INVALID EXAMPLES
-----------------
❌ (empty)              (At least 1 subject required)
❌ 999|111|121          (Subject 999 doesn't exist)
❌ 111,121,131          (Must use pipe |, not comma)

IMPORT PROCESS
---------------
1. Go to: Registration → Candidates
2. Click: "Bulk Import CSV" button
3. Upload: CSV file with PRIVATE candidates
4. Select: Mode (Skip or Replace)
5. Select: Exam Year (e.g., 2026)
6. Click: "Validate"
7. Review: Results
8. Click: "Commit/Import"
9. Verify: "Allocated Subjects" column in /exam-types/acsee

COMMIT RESPONSE
----------------
"Imported X candidates, allocated subjects for Y"

Example:
"Imported 2 candidates, allocated subjects for 7"
= 2 PRIVATE candidates imported with 7 total subject allocations

DATABASE STORAGE
-----------------
All allocations stored in: candidate_subject_selections
Fields:
  - candidate_id: The PRIVATE candidate
  - exam_type_id: 1 (ACSEE)
  - exam_year_id: 3 (2026)
  - subject_id: Database ID of the subject
  - is_principal: 1 (all PRIVATE subjects are marked as principal)
  - source: 'import'
  - is_active: 1

TROUBLESHOOTING
-----------------
Problem: "No valid subjects found for candidate X"
  → Check that subject codes exist in database
  → Verify no typos in subject codes

Problem: "subjects are required for PRIVATE candidates"
  → Ensure "subjects" column is present in CSV
  → Ensure subjects are provided (not empty)

Problem: "Subject not found: 999"
  → Subject code 999 doesn't exist
  → Check valid subject codes listed above

WHAT DIFFERS FROM SCHOOL CANDIDATES?
--------------------------------------
SCHOOL Candidates:
  - Require: "combination" column (e.g., "MAA", "MMB")
  - Subjects auto-allocated from combination definition
  - Must follow NECTA principal subject rules

PRIVATE Candidates:
  - Require: "subjects" column with pipe-delimited codes
  - Subjects manually specified in CSV
  - NO NECTA rules - any subject combination allowed
  - GS is optional (unlike SCHOOL candidates)
