📋 FEATURE SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Users can now choose how to handle existing candidates during bulk imports:

  MODE: SKIP (Default)           MODE: REPLACE
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  • Don't overwrite               • Update existing candidate info
  • Create new candidates only    • Updates: name, gender, school
  • Safest option                 • Immutable: ID, exam type, marks
  • Default behavior              • Use for corrections/reassignments


📱 USER WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Open Candidates page
2. Click Tools > Import CSV
3. Select template (School or Private)
4. Choose mode: Skip OR Replace (radio buttons)
5. Upload CSV file
6. Click "Validate" → Review Import Plan table
7. Check summary cards:
   - Total Rows
   - New (will create)
   - Will Skip or Will Update (depends on mode)
   - Errors
   - Can Import (Yes/No)
8. If Replace: Read orange warning
9. Click "Import X Records"
10. Wait for completion → Success message

🛡️ DATA SAFETY RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

REPLACE Mode UPDATES:          REPLACE Mode PROTECTS:
✅ full_name (name)            ❌ candidate_id (never changed)
✅ gender (M/F)                ❌ exam_type (ACSEE/PSLE/CSEE)
✅ school_id                   ❌ combination (subject combo)
                               ❌ exam registrations (preserved)
                               ❌ marks (never deleted)
                               ❌ results (never deleted)

Why? Changing exam type/combination could orphan marks and break results!


🔧 API ENDPOINTS (For Developers)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

POST /api/candidates/import/validate
  Parameters:
    - file (CSV)
    - exam_year (optional)
    - exam_type (optional)
    - on_exists_mode: "skip" or "replace" (default: "skip")
  
  Returns:
    - create_count, update_count, skip_count, error_count
    - rows: array of row statuses (NEW, SKIP, REPLACE, ERROR)
    - can_import: boolean


POST /api/candidates/import/commit
  Parameters:
    - file (CSV, same as validate)
    - exam_year (optional)
    - exam_type (optional)
    - on_exists_mode: "skip" or "replace" (must match validate)
  
  Returns:
    - imported_count, updated_count, skipped_count
    - errors: array of validation failures

🐛 TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem: "Can Import" shows No
→ Fix errors in your CSV (see Error table)

Problem: "Already exists" error in Skip mode
→ This is normal! Change to Replace if you want to update

Problem: Name didn't update (Replace mode)
→ Check school code exists; try again

Problem: Import failed halfway
→ Check logs (storage/logs/laravel.log)
→ All-or-nothing: either all succeeds or all rolls back

Problem: Marks disappeared
→ Not possible! Replace mode never deletes marks

❓ FAQ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Will Replace delete the candidate?
A: No! Only updates name/gender/school. ID, exam type, marks preserved.

Q: What if I import same file twice with Skip?
A: First time creates candidates. Second time skips all (nothing happens).

Q: Can I undo an import?
A: Not automatically. Check import report to see what was created/updated.

Q: What's the file size limit?
A: 50 MB maximum per import.

Q: Does Replace mode delete marks?
A: NO. Replace mode is specifically designed to never touch marks/results.

Q: What fields can Replace update?
A: Only: full_name, gender, school_id
  Cannot update: candidate_id, exam_type, combination, subject selections

Q: What if school code is wrong in Replace?
A: Import will fail. Error table shows which row has bad school code.
