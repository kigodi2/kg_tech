SCENARIO 1: Normal Operation
───────────────────────────
1. User clicks "Bulk Import CSV"
   → Modal opens
   → Spinner appears: "Loading exam years…"
   → All buttons/inputs disabled (grayed out)

2. API fetches data (~50-200ms)
   → Options load: exams, combinations, subjects

3. Data arrives
   → Spinner disappears
   → Buttons/inputs enabled (normal state)
   → Active exam year auto-selected
   → User can interact

SCENARIO 2: API Failure
───────────────────────
1. User clicks "Bulk Import CSV"
   → Modal opens
   → Spinner appears

2. API fails (network error, 500, etc.)
   → Error caught
   → Error logged to console
   → bulkErrorMessage set

3. After loading stops
   → Spinner disappears
   → Red error banner shows: "Unable to load exam years. Please refresh the page or try again."
   → Buttons/inputs stay disabled
   → User can close modal and retry

 BEFORE vs AFTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BEFORE (Without Hardening):
───────────────────────────
1. Click "Bulk Import"
2. Modal opens immediately
3. No visual feedback (silent)
4. API requests start
5. If slow: user doesn't know if anything is happening
6. If error: silent failure, nothing shows
7. If error: console shows errors but user doesn't see

AFTER (With Hardening):
───────────────────────
1. Click "Bulk Import"
2. Modal opens immediately
3. Spinner shows: "Loading exam years…"
4. Buttons/inputs disabled (clear they can't interact)
5. API requests start
6. User sees activity (spinner)
7. If slow: spinner keeps going, user knows it's working
8. If error: Red banner appears with clear message
9. Error also logged to console for developers

✅ Network timeouts → Caught by catch block
✅ Malformed JSON → Safe parsing with fallback
✅ Missing API properties → Uses || operator for defaults
✅ UI crashes → finally block ensures cleanup
