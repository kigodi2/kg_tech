================================================================================
KEY ARCHITECTURAL CHANGES
================================================================================

BEFORE (Wrong):
  User Input → Combination Selection → Upload CSV → Store Combination
  ❌ Combination is a CANDIDATE property, not an import input

AFTER (Correct):
  User Input → Upload CSV → Derive Combination from Registration → Validate
  ✅ Combination is derived dynamically from candidate data

VALIDATION FLOW:
  1. Parse CSV
  2. For each row:
     a. Find candidate by index_number
     b. Check ACSEE registration for year
     c. Get candidate's selected subjects
     d. Derive combination containing ALL subjects
     e. Validate uploaded subject is in that combination
     f. Validate marks (range, structure)
     g. Accept or reject row with clear error

DATA MODEL CHANGES
================================================================================

Candidate
  ├── CandidateExamRegistration (year 2025, ACSEE)
  │   └── List of registered combinations
  │
  ├── CandidateSubjectSelection (year 2025, ACSEE)
  │   ├── Subject 1
  │   ├── Subject 2
  │   └── Subject 3
  │
  └── [System derives] → Combination containing ALL subjects

EXAMPLE:
Student has selected: Physics, Chemistry, Biology
→ System finds "Science Combination" (contains Physics, Chem, Bio)
→ Upload Biology marks
→ ✅ Valid (Bio is in Science combo)
