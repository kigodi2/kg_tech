KEY FACTS (MEMORIZE)
================================================================================

1. CSV FORMATS (NEW)
   SCHOOL: exam_year, index_number, combination_code, replace_allocations
   PRIVATE: exam_year, index_number, subject_codes (pipe-separated), replace_allocations

2. VALIDATION RULES (REUSE)
   - General Studies (111) mandatory
   - Minimum 3 principal subjects (excluding GS)
   - No duplicates
   → Use: AcseeAllocationValidator::validate()

3. CANDIDATE MATCHING (NEW FOR CSV)
   - Match by: index_number (from CSV) + exam_year_id (from UI)
   - Not by: candidate ID (that's for single-step allocation)

4. IDEMPOTENCY (EXISTING PATTERN)
   - updateOrCreate() with unique key: (candidate_id, exam_type_id, exam_year_id, subject_id)
   - Re-import same CSV = safe, no duplicates

5. TWO-PHASE FLOW (EXISTING PATTERN)
   - Phase 1 (validate): Read CSV, no DB changes, return errors
   - Phase 2 (commit): Apply changes to DB only after user confirms

6. SAFEGUARDS (EXISTING + NEW)
   - Replace mode is opt-in (defaults to add-only)
   - Explicit confirmation before destructive operations
   - Detailed error reporting per row
   - Downloadable error CSV

7. REUSE (CRITICAL)
   - AcseeAllocationValidator (validation rules)
   - CandidateImportService pattern (CSV parsing)
   - updateOrCreate() (idempotency)
   - Two-phase pattern (validate + commit)
   - CandidateImportController structure (endpoints)

8. DON'T REINVENT
   - Don't create new validation logic (use AcseeAllocationValidator)
   - Don't create new CSV parsing patterns (follow CandidateImportService)
   - Don't create new error handling (reuse existing patterns)
