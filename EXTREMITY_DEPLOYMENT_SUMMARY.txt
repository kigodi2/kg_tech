A comprehensive system to detect candidates with suspicious cross-subject score
patterns by analyzing performance anomalies within each candidate's own subjects.

Identifies when a candidate performs extremely well or poorly in one subject
compared to their other subjects, flagging potential:
  • Marking errors
  • Cheating patterns
  • Health/personal issues
  • Exam administration problems
  • Data entry errors

================================================================================
ANALYSIS METHODOLOGY
================================================================================

Per-Candidate Statistical Analysis:

1. COLLECT DATA
   - Get all subjects candidate is registered for
   - Get marks for each subject
   - Require minimum 3 subjects to analyze

2. CALCULATE STATISTICS
   - Mean (average) score across subjects
   - Median score
   - Standard Deviation (score spread)
   - Min/Max scores
   - Quartiles for reference

3. DETECT OUTLIERS (Two methods)
   
   Method A: Z-Score
   - Z = (Score - Mean) / StdDev
   - Threshold: |Z| > 2.0
   - Detects extreme deviations
   
   Method B: Percentage Deviation
   - Deviation = Score - Mean
   - Deviation % = (Deviation / Mean) * 100
   - Threshold: >20% (positive or negative)
   - Catches moderate deviations

4. ASSESS RISK
   - Count outlier subjects
   - Check for patterns
   - Evaluate standard deviation
   - Assign risk level:
     * High: 50%+ subjects are outliers or 3+ flags
     * Moderate: 33-50% outliers or 1-2 flags
     * Low: <33% outliers and no flags

5. GENERATE FLAGS
   - "Multiple Subject Outliers"
   - "Several Subject Anomalies"
   - "Single Subject Outlier"
   - "Extreme Subject Deviation"
   - "Uniform Performance"

WHAT GETS FLAGGED (EXAMPLES)

SCENARIO 1: Subject-Level Outlier
  Candidate: John Doe
  Subjects: Physics (85), Chemistry (88), Math (18)
  Average: 63.7
  Flag: Single Subject Outlier (Math extremely low)
  Risk: Moderate → High if extreme
  Possible Issue: Math marking error or student distress

SCENARIO 2: Multiple Outliers
  Candidate: Jane Smith
  Subjects: English (92), Kiswahili (88), CRE (35), History (40)
  Average: 64
  Flag: Multiple Subject Anomalies
  Risk: High
  Possible Issue: Humanities strong, but Sciences weak (pattern)

SCENARIO 3: Suspicious Clustering
  Candidate: Bob Wilson
  Subjects: Physics (75), Chemistry (76), Math (77), Biology (78)
  StdDev: 1.0 (too similar)
  Average: 76.5
  Flag: Uniform Performance (Suspiciously Similar)
  Risk: High if other outliers present
  Possible Issue: Copied answers or exam misconduct

SCENARIO 4: Extreme Spread
  Candidate: Alice Johnson
  Subjects: Subject A (5), Subject B (15), Subject C (95), Subject D (100)
  StdDev: 45.2 (very high)
  Flag: Extreme Subject Deviation
  Risk: High
  Possible Issue: Student unprepared in some subjects

DATABASE SCHEMA OVERVIEW
================================================================================

candidate_extremity_analysis
├─ id (primary key)
├─ candidate_id → candidates.id
├─ exam_year_id → exam_years.id
├─ exam_type_id → exam_types.id
├─ combination: string (e.g., "PCM")
├─ subject_count: integer
├─ average_score: decimal(8,3)
├─ median_score: decimal(8,3)
├─ std_dev_across_subjects: decimal(8,3)
├─ min_score, max_score: decimal(8,3)
├─ outlier_subject_count: integer
├─ outlier_subjects: json (array of outlier data)
├─ subject_analysis: json (per-subject details)
├─ risk_level: enum (Low, Moderate, High)
├─ flags: json (array of strings)
├─ reviewed: boolean
├─ reviewed_at, reviewed_by: timestamps/FK
├─ review_notes: text
└─ created_at, updated_at, deleted_at: timestamps

candidate_subject_outliers
├─ id (primary key)
├─ candidate_extremity_id → candidate_extremity_analysis.id
├─ subject_id → subjects.id
├─ score: decimal(8,3)
├─ candidate_average: decimal(8,3)
├─ deviation_from_average: decimal(8,3)
├─ deviation_percentage: decimal(8,3)
├─ zscore: decimal(8,3)
├─ outlier_type: enum (high, low)
└─ created_at, updated_at: timestamps

candidate_extremity_logs
├─ id (primary key)
├─ exam_year_id, exam_type_id: FKs
├─ candidates_analyzed: integer
├─ high_risk_count, moderate_risk_count, low_risk_count: integers
├─ total_outliers_detected: integer
├─ analysis_started_at, analysis_completed_at: datetimes
├─ status: enum (pending, processing, completed, failed)
├─ error_message: text
├─ triggered_by: FK to users
└─ created_at, updated_at: timestamps
