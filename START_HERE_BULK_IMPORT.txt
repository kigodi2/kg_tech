⚠️ CRITICAL REMINDERS
════════════════════════════════════════════════════════════════════════════════

1. CLEAR BROWSER CACHE FIRST
   This is essential! Without it, old cached code will interfere.
   Ctrl+Shift+Delete → Clear Cache

2. DON'T RENAME CSV FILES
   System depends on exact filenames.
   If you rename them, the import breaks.

3. SAVE ALL CSVS BEFORE UPLOADING
   Keep Excel files closed to avoid file locks.

4. USE FRESH ZIP FROM SYSTEM
   Don't use manually modified ZIPs for testing.

5. BACKUP DATABASE
   Always backup before first production import.

❓ FAQ
════════════════════════════════════════════════════════════════════════════════

Q: Do I need to do anything special to activate the system?
A: No. Just clear browser cache and start using it.

Q: Is the manifest.json created automatically?
A: Yes. Every ZIP download includes it automatically.

Q: What if I download a ZIP but don't use it right away?
A: You can use it anytime. The manifest.json is embedded in the ZIP.

Q: Can I edit CSV filenames?
A: No. Don't rename CSV files - the system depends on exact names.

Q: How long does import take?
A: About 1 second per 100 candidates. 2400 candidates ≈ 24 seconds.

Q: Where are marks saved?
A: In the database, in the marks table, with audit timestamps.

Q: What if import fails?
A: Check the error message, fix the CSV, re-upload and try again.

Q: Can I import the same ZIP twice?
A: Technically yes, but you shouldn't - no duplicate prevention.

Q: Is my data safe?
A: Yes. All operations are logged, checksums verify integrity, backups available.

Q: Who can I contact for help?
A: See QUICK_REF_BULK_IMPORT.txt for support escalation process.
