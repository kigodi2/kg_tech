DATABASE SCHEMA (KEY ELEMENTS)
================================================================================

NEW TABLE: exam_years
  id              INT PRIMARY KEY AUTO_INCREMENT
  year_label      VARCHAR(9) UNIQUE        -- "2024", "2023-2024"
  is_active       BOOLEAN DEFAULT FALSE    -- Only 1 TRUE at a time
  is_locked       BOOLEAN DEFAULT FALSE    -- TRUE after publish
  published_at    TIMESTAMP NULL           -- When results published
  locked_at       TIMESTAMP NULL           -- When locked

MODIFIED TABLES: candidates, registrations, marks, results, etc.
  exam_year_id    INT NOT NULL            -- FK to exam_years
  + Foreign key constraint (ON DELETE RESTRICT)
  + Triggers to prevent writes to locked years

CONSTRAINTS:
  ✓ Only 1 active year (CHECK constraint)
  ✓ Locked = published (CHECK constraint)
  ✓ Foreign key on all exam tables
  ✓ Triggers prevent writes to locked years

PYTHON SERVICE LAYER (KEY PATTERN)
================================================================================

ALL Methods Now Require exam_year_id (MANDATORY)

BEFORE:
  service.get_registered_candidates(subject_id=5, school_id=10)

AFTER:
  service.get_registered_candidates(subject_id=5, school_id=10, exam_year_id=1)

ERROR HANDLING:
  ExamYearRequiredError   - Year missing or invalid
  YearLockedError         - Cannot write to locked year

VALIDATION:
  Every method calls:
  1. _validate_exam_year(exam_year_id)    -- Fail if invalid
  2. _check_year_not_locked(exam_year_id) -- Fail if locked (before write)

API INTEGRATION

EXTRACT exam_year_id FROM REQUEST:

    GET /api/candidates?exam_year_id=1

  Option 2: HTTP header
    GET /api/candidates -H "X-Exam-Year-ID: 1"

  Option 3: JSON body
    POST /api/candidates -d '{"exam_year_id": 1, ...}'

MIDDLEWARE:
  @require_exam_year decorator extracts and validates
  Stores in g.exam_year_id for use in route

ERROR RESPONSES:
  400 Bad Request      - Missing exam_year_id
  422 Unprocessable    - Invalid exam_year_id
  423 Locked           - Year locked (read-only)

COMMON ISSUES & SOLUTIONS
================================================================================

"Duplicate column name"
  → Column already exists from previous attempt
  → DROP COLUMN and retry

"Foreign key constraint fails"
  → exam_year_id references non-existent year
  → Run validation queries to find orphaned values
  → Either update to valid year or backfill again

"Only one active year allowed" error
  → Multiple years marked as active
  → Use stored procedure: CALL deactivate_all_other_years(@year_id)

"Cannot write to locked year"
  → This is EXPECTED behavior when year is locked
  → Use API to publish (lock) intentionally
  → Only published years should be locked

Migration hangs/slow
  → Long-running UPDATE on large table
  → Monitor progress: SELECT COUNT(*) FROM candidates WHERE exam_year_id=0;
  → Check SHOW PROCESSLIST if stuck
