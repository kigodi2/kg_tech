KEY FEATURES
================================================================================

✅ AUTOMATIC ALLOCATION
   Import CSV with subjects column → automatically allocates

✅ NECTA COMPLIANCE
   Uses existing AcseeAllocationValidator:
   - General Studies (111) mandatory
   - Minimum 3 principal subjects required
   - No duplicates
   - All subjects must exist in system

✅ SAFE
   - Marks never deleted
   - Registrations preserved
   - Results protected
   - Only candidate_subject_selections modified

✅ IDEMPOTENT
   - SKIP mode: reimport unchanged (candidate exists)
   - REPLACE mode: reallocates only for that candidate/exam year
   - Unique constraints prevent duplicates

✅ SUBJECT FORMAT FLEXIBLE
   - Pipe-delimited: "111|102|103|121"
   - Codes or IDs: both supported
   - "111|102|103|121" or "1|2|3|4"

✅ ERROR HANDLING
   - Allocation errors non-fatal (candidate still imported)
   - Validation errors prevent import
   - Detailed error messages in response

✅ BACKWARD COMPATIBLE
   - SCHOOL candidates unaffected
   - CSV import without subjects column still works
   - No breaking changes to existing workflows

================================================================================
VALIDATION RULES
================================================================================

MANDATORY:
  - General Studies (code 111) required

MINIMUM:
  - 4 subjects total: 1 GS + ≥3 principals
  - Example: "111|102|103|121" ✓
  - Example: "111|102|103" ✗ (only 2 principals)

DUPLICATES:
  - Automatically deduplicated
  - Example: "111|102|102|103" → "111|102|103"

ALL SUBJECTS:
  - Must exist in database
  - Check admin > Subjects for available codes

================================================================================
CSV FORMAT
================================================================================

REQUIRED COLUMNS (existing):
  candidate_id, full_name, gender, school_code, candidate_type, exam_type, exam_year

NEW COLUMN (optional, for PRIVATE only):
  subjects: pipe-delimited subject codes or IDs

EXAMPLE:
candidate_id,full_name,gender,school_code,candidate_type,subjects,exam_type,exam_year
P0001-0001,John Private,M,SCH001,PRIVATE,111|102|103|121,ACSEE,2026
P0002-0001,Jane Private,F,SCH001,PRIVATE,111|104|121|122,ACSEE,2026
S0001-0001,School User,M,SCH001,SCHOOL,,ACSEE,2026

Note: School candidates don't need subjects column (uses combination instead)

================================================================================
TROUBLESHOOTING
================================================================================

"Allocations not showing?"
  → Refresh browser
  → Check candidate_subject_selections table directly
  → Verify allocations created in DB: 
     SELECT * FROM candidate_subject_selections 
     WHERE candidate_id = <id>

"General Studies mandatory error"
  → Add code 111 to subjects: "111|102|103|121"

"Minimum 3 principals error"
  → GS doesn't count; need GS + 3 others
  → Invalid: "111|102|103" (only 2 principals)
  → Valid: "111|102|103|121" (3 principals + GS)

"Subject not found"
  → Check admin > Subjects for available codes
  → Verify subject code matches database

"Marks deleted?"
  → No. Marks are safe. Only allocations modified.
